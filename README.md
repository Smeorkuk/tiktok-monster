# Насколько ты TikTok-монстр?

Публичный сайт: https://smeorkuk.github.io/tiktok-monster/

Админка: https://smeorkuk.github.io/tiktok-monster/admin/

Архив: https://smeorkuk.github.io/tiktok-monster/archive/

Интерфейс теста, админка и архив размещены на GitHub Pages. API, вопросы, режимы, результаты и загрузки изображений обслуживает Supabase. Старый сервер ChatGPT Sites для работы GitHub-сайта больше не нужен. Существующий пароль администратора сохранён.

## Возможности

- Статистика попыток: ник, ответы, время, баллы, фильтры, разбор и CSV.
- Редактор вопросов: текст, картинка, год, сложность, пояснение, источники, от 1 до 10 вариантов или письменный ответ с дополнительными правильными написаниями.
- Скрытие вопросов без потери старых прохождений; новые вопросы можно сохранить как черновики.
- Редактор режимов: название, описание, число вопросов, ручной состав, порядок, видимость, добавление и удаление. Число 0 означает все доступные вопросы. Фильтр годов игрока дополнительно ограничивает состав.
- Для начатых попыток сохраняется снимок вопросов, поэтому последующие правки не меняют их оценку.
- Исследовательский архив: 230 карточек и 99 изображений, исходные материалы, таблица и JSON. Архив исследования и редактируемый каталог игровых вопросов — отдельные наборы.

## Разработка и публикация

Node.js 22.13+, сторонних npm-зависимостей нет.

```sh
npm run build
npm test
npm run dev
npm run build:pages
node scripts/build-edge.mjs
```

`web/` содержит интерфейс. `worker/index.mjs` — исходник API и локального сервера. `scripts/build-edge.mjs` собирает API для Supabase в `supabase/functions/quiz-api/api.mjs`; `edge.mjs` подключает Postgres и Storage. `supabase/config.toml` сохраняет настройки функции. Локальные миграции SQLite находятся в `drizzle/`; рабочая Postgres-база уже создана.

Локальный сервер использует тестовую административную идентичность только с `LOCAL_DEV: true`. Этот режим запрещено включать на публичном сервере. Локальная база и загрузки находятся в `.local/` и исключены из Git.

`npm run build:pages` создаёт папку `pages/`. Её содержимое публикуется в корне ветки `gh-pages`, выбранной в GitHub Pages. В `admin/index.html` используется относительный base, поэтому вложенный путь репозитория работает корректно. `admin.html` также доступен для совместимости.

## Доступ и данные

Вход проверяется API по PBKDF2-хешу, сессия подписывается HMAC и действует 12 часов; попытки входа ограничены. GitHub-админка передаёт сессию в заголовке Authorization и хранит её только в sessionStorage текущей вкладки. Выход удаляет локальную сессию. Пароли, ключи подписи и сервисные ключи в GitHub не хранятся.

Публичные таблицы Supabase закрыты RLS без клиентских политик: доступ к ним выполняет только серверный API, который проверяет права администратора или токен игрока. Доверенный заголовок личности Sites удаляется на входе в Edge Function. CORS ограничен origin GitHub Pages. `verify_jwt = false` сохранён намеренно: функция использует собственную проверку подписанной административной сессии, а игрокам регистрация не нужна.

Вопросы, режимы и новые изображения из редактора сохраняются в Supabase без пересборки GitHub Pages. Загружаются PNG/JPG/WebP до 2 МБ. Статический архив изменяется через репозиторий. Для проверки изображений используются сигнатуры файлов.

Игрок сам выбирает ник; это не подтверждённая личность. Перед прохождением он соглашается сохранить ник, ответы, баллы и время. Данные попыток не должны попадать в GitHub. Тест показывает ответы в браузере и не предназначен для защищённых экзаменов.

Исследование отражает срез на 12 ноября 2026 года и содержит отмеченные пробелы. Изображения принадлежат их авторам; ссылки на источники сохранены.
